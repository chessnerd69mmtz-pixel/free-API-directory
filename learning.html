1. Your First API: What Are You Actually Doing?

By the end, you can explain an API and identify the client, server, endpoint, request, and response.

Start here: No programming experience is required. We begin with a restaurant analogy.

Step 1 — Imagine ordering food

You tell a waiter what you want. The waiter takes the order to the kitchen and brings the result back. You = client, waiter = API, kitchen = server, order = request, meal = response.

Step 2 — Translate the analogy

Client

Your website, script, mobile app, or backend.

Server

The system that receives the request and does the work.

Endpoint

A specific API address such as /weather.

Request

What your program sends.

Response

What the API sends back.

Step 3 — Read a request

GET https://api.example.com/weather?city=Bengaluru

GET means retrieve. /weather identifies the operation. city=Bengaluru supplies a value.

Step 4 — Read the response

{ "city": "Bengaluru", "temperature_c": 27.4, "conditions": "Cloudy" }

Your program can turn these values into a card, chart, alert, or recommendation.

Do this now: Explain the restaurant analogy out loud, then explain an API without using the word “API.”
Common mistake: An API is not necessarily a database. Behind an API can be a database, calculation, AI model, or several services.
Checkpoint: In GET /books/42, what is /books/42?
It is the endpoint/path identifying the requested resource: book 42.

2. Sending a Request: HTTP From Zero

Learn the four pieces you see constantly: method, URL, headers, and body.

Step 1 — Start with the URL

https://api.example.com/v1/books

https:// is the protocol, api.example.com is the host, and /v1/books is the path.

Step 2 — Choose the method

MethodBeginner translation
GETGive me information.
POSTHere is data; create/process it.
PUTReplace this resource.
PATCHChange part of this resource.
DELETERemove this resource.

Step 3 — Query parameters

GET /books?author=tolkien&limit=10

? starts the query string and & separates parameters.

Step 4 — Headers

Accept: application/json
Authorization: Bearer YOUR_TOKEN

Headers carry metadata or credentials. The exact names depend on the provider.

Step 5 — Request body

{ "name": "Aryan", "email": "example@email.com" }

A body carries structured data you are sending, commonly with POST, PUT, or PATCH.

Practice: Label POST https://api.example.com/users: POST = method, URL = destination, JSON = body.
Common mistake: Never assume an endpoint accepts every method. Follow its documentation.

3. Reading Responses Without Getting Lost

Learn to tell whether a request worked and how to safely read JSON.

Step 1 — Check the status code

CodePlain English
200Success.
201Created successfully.
400Your request is invalid.
401Authentication is missing/invalid.
403You are not allowed to do that.
404Resource/endpoint not found.
429Too many requests.
500+Server-side failure.

Step 2 — Read JSON

{ "name": "Ada", "age": 36, "skills": ["math", "programming"], "student": false }

name is text, age a number, skills an array, and student a boolean.

Step 3 — Validate important fields

if (typeof data.temperature_c !== "number") {
  throw new Error("Temperature is missing");
}

APIs can omit fields or return null. Robust applications check what they receive.

Step 4 — Separate request failure from data problems

A 401 is an authentication problem. A 200 with an unexpected field is a response-shape problem. Different symptoms need different debugging.

Practice: For HTTP 429, investigate rate limits and quota before changing your JSON parser.
Checkpoint: What should you check first for a 401?

4. API Keys and Authentication — Step by Step

Understand why credentials exist, where they go, and how to protect private secrets.

Step 1 — Why keys exist

Providers may use credentials to identify an application, apply quotas, control access, and reduce abuse.

Step 2 — Recognize common formats

X-API-Key: YOUR_KEY

Authorization: Bearer YOUR_TOKEN

These are examples, not universal rules. Always follow provider documentation.

Step 3 — Distinguish public and private credentials

Some credentials are intentionally browser-safe and restricted. A private server secret is different: it should not be shipped to every visitor.

Step 4 — Store a server secret safely

# .env
API_KEY=your-real-secret

# server-side code
const key = process.env.API_KEY;

Production apps should use the hosting platform's secret/environment system or a secret manager.

Step 5 — If a key leaks

  1. Assume it is compromised.
  2. Revoke/rotate it.
  3. Remove it from exposed code/history where appropriate.
  4. Check logs, screenshots, builds, and repositories.
  5. Replace it with a safer credential flow.
Common mistake: Renaming or hiding a key in frontend JavaScript does not make it secret. Browser-delivered code can be inspected.
Exercise: Pick one directory provider and write down its authentication method, where the credential goes, whether it is required, and whether browser use is supported.

5. “Free” Does Not Always Mean the Same Thing

Learn how to investigate a free API before building around it.

Step 1 — Identify what is actually free

Ask: permanent free tier, recurring quota, temporary trial, free credits, or community endpoint? Is a card required? Does the free allowance cover your endpoint?

Step 2 — Learn four kinds of limits

Quota

Total included in a period.

Rate limit

How quickly requests may be sent.

Endpoint limit

A specific operation may have its own cap.

Credits

Usage may consume a balance instead of simple requests.

Step 3 — Calculate your workload

If one user generates 20 requests/day and you expect 100 users:

20 × 100 × 30 = 60,000 requests/month

This is only a request-count estimate. You still need to check rate limits, endpoint limits, tokens, and terms.

Step 4 — Verify with the provider

Use this directory for discovery, then read the provider's current official pricing, limits, authentication, and terms pages before relying on a quota.

Exercise: Pick one provider and create a five-line free-tier card: authentication, allowance, rate limit, card/account requirement, and official source checked.
Common mistake: “Free” does not mean unlimited.
Practice with Free-Tier Calculator

6. Choosing an API: A Repeatable Process

Learn how to choose based on requirements rather than a free badge.

Step 1 — Describe your feature

Instead of “I need an AI API,” write “I need to classify 5,000 short messages each month and receive a label within two seconds.” Requirements make comparison possible.

Step 2 — Write your constraints

  • What data do you need?
  • How many requests?
  • Browser or server?
  • Commercial use?
  • Region?
  • Latency?
  • Can users provide their own key?

Step 3 — Discover candidates

Use the Use Case Explorer, then the Finder to narrow candidates.

Step 4 — Verify

Check authentication, allowance, limits, endpoints, terms, browser restrictions, and current official documentation.

Step 5 — Test a tiny proof of concept

Make one real request. Measure response time, inspect the response, and intentionally test one failure.

Exercise: Compare two candidates in a table with capability, authentication, free allowance, rate limit, browser support, terms, documentation, and evidence date.

7. Build Your First Integration From Scratch

Go from “I found an API” to “my program uses it safely.”

Step 1 — Read the endpoint documentation

Find the URL, method, parameters, authentication, response format, and errors before coding.

Step 2 — Make the smallest request

async function getWeather(city) {
  const url = "https://api.example.com/weather?city=" + encodeURIComponent(city);
  const response = await fetch(url);
  if (!response.ok) throw new Error("HTTP " + response.status);
  return await response.json();
}

Step 3 — Inspect the real response

Do not invent field names. Look at the actual response and identify the values you need.

Step 4 — Transform provider data

const result = {
  city: data.city,
  temperature: data.temperature_c,
  summary: data.conditions
};

Step 5 — Add failure handling

Handle network errors, non-2xx responses, malformed data, timeouts, and rate limits.

Step 6 — Isolate provider-specific code

Keep provider calls inside a small adapter so changing providers later is easier.

Exercise: Pick a keyless public API from the directory and make one page with one input, one button, one loading state, one result, and one error message.

8. Debugging: Find the Broken Layer

Use evidence instead of random edits.

Step 1 — Check the URL

Verify protocol, host, version, path, parameters, and resource IDs.

Step 2 — Check authentication

Confirm whether a credential is needed, whether it is active, and whether it is placed correctly.

Step 3 — Read the exact status code

401, 403, 404, 429, and 500+ suggest different investigations.

Step 4 — Compare against the provider example

Run the smallest documented example and compare it with your request line by line.

Step 5 — Check the environment

Browser CORS, DNS, proxies, firewall rules, environment variables, and deployment configuration can affect results.

ErrorStart here
401Credential and auth format
403Permissions/plan/restrictions
404URL/path/version/resource
429Rate limit/quota/concurrency
5xxProvider status/transient failure
CORSBrowser policy/provider browser support
Exercise: For a fake 429 error, write three possible causes before changing code. This builds evidence-based debugging habits.

9. Security: Protect Keys and User Data

Learn the minimum security habits every API beginner should adopt.

Step 1 — Classify the credential

Determine whether it is intentionally browser-safe or a private server secret.

Step 2 — Keep private secrets server-side

Browser → Your backend → Provider API
          ↑ secret lives here

Step 3 — Control logging

Do not log tokens, Authorization headers, passwords, or unnecessary personal data.

Step 4 — Validate user input

Check size, type, format, and allowed values before forwarding data to another service.

Step 5 — Plan for exposure

Have a rotation/revocation process before a leak occurs.

Common mistake: Base64 encoding, minifying, or renaming a frontend key does not make it secret.
Exercise: Draw your request path and circle where the private credential lives. If it is inside browser-delivered code, reconsider the architecture.

💻 Vibecoding From Scratch

A slow, friendly introduction to building things with AI. This course assumes you have never written code before. You do not need to know what HTML, JavaScript, GitHub, a terminal, or a framework is.

Important: Vibecoding does not mean “ask AI for an app and hope it works.” It means using AI as a coding partner while you gradually learn what the pieces mean, how to give useful instructions, how to test the result, and how to fix mistakes.
Absolute beginner15 min

V1. What Even Is Code?

Understand the basic idea of code before touching an AI coding tool.

Step 1 — Think about instructions

Imagine telling a robot: “Make me a sandwich.” A human can fill in missing details. A computer cannot. You would need instructions such as: get bread, put bread on a plate, add filling, put the second slice on top.

Step 2 — Code is instructions

Code is a set of instructions written in a language a computer can process. Different languages are designed for different jobs. You do not need to memorize a language to begin vibecoding.

Step 3 — A program is a collection of instructions

A tiny program might say “show this message.” A larger program might contain thousands or millions of instructions that work together.

Step 4 — Code is stored in files

Code usually lives in text files. For example, index.html can contain the structure of a webpage and app.js can contain JavaScript instructions.

Say this aloud: “Code is instructions. A program is code working together. A file is where some of that code is stored.” If those three sentences make sense, you are ready for the next lesson.
Do not worry about this yet: variables, functions, classes, frameworks, APIs, Git, npm, deployment, and databases. We will introduce concepts only when we need them.
Absolute beginner15–20 min

V2. What Are Files, Folders, and a Website?

Understand where your code lives and what you are actually building.

Step 1 — A folder is a container

Think of a folder like a physical project box. Your project can contain many files inside it.

Step 2 — A file has a job

A project might contain index.html, style.css, and app.js. They are simply different files containing different kinds of instructions.

Step 3 — HTML is the structure

HTML tells the browser what things exist: headings, paragraphs, buttons, images, forms, and other elements.

<h1>My First Website</h1>
<p>Hello!</p>

Step 4 — CSS controls appearance

h1 {
  font-size: 40px;
}

CSS can control spacing, sizes, fonts, layouts, borders, and many other visual properties.

Step 5 — JavaScript adds behavior

button.addEventListener("click", () => {
  alert("Hello!");
});

JavaScript can respond to clicks, change the page, request data, calculate things, and much more.

Beginner exercise: Open any webpage and right-click → Inspect if your browser offers that option. You do not need to understand the panel. Just notice that a webpage is made from inspectable pieces.
Absolute beginner15 min

V3. What Is Vibecoding?

Understand the basic AI-assisted coding loop without getting overwhelmed.

Step 1 — You describe the goal

Instead of writing every instruction yourself, you can tell an AI coding assistant what you want.

“Make a webpage with a large title,
a text box, and a button.
When I click the button, show
the text I entered below it.”

Step 2 — AI turns the description into code

The AI may create HTML, CSS, and JavaScript. Your job is not to pretend you understand every line immediately.

Step 3 — You run it

Open the page or run the project. Look at what actually happened.

Step 4 — You describe the problem

If the button does nothing, tell the AI exactly that. Do not randomly rewrite everything.

Step 5 — Repeat

This creates the basic vibecoding loop:

Describe → Generate → Run → Observe → Explain problem → Fix → Repeat
Important: “Vibecoding” should not mean blindly accepting code you do not understand. The goal of this course is to help you understand a little more after every iteration.
Absolute beginner20 min

V4. Your First Vibecoding Prompt

Learn how to ask an AI coding assistant for something small enough to succeed.

Step 1 — Start tiny

Do not begin with “Build me the next Instagram.” Begin with one visible feature.

Step 2 — Say what you want

Build a simple webpage.
Put a heading saying “My First App”.
Add a button saying “Click me”.
When the button is clicked,
show “It works!” underneath it.

Step 3 — Tell the AI your skill level

I am a complete beginner.
Keep the code simple.
Explain what each file does.
Do not introduce frameworks yet.

Step 4 — Ask for instructions, not just code

A good beginner prompt asks the AI to tell you which files to create, where to put them, how to run the result, and what each file is doing.

Step 5 — Build one thing at a time

Once the button works, ask for the next feature. This is much easier to debug than asking for 30 features at once.

Copy this mental template: “I am a beginner. I want to build ____. First help me make the smallest working version. Tell me what each file does and how to test it. Do not add extra features yet.”
Absolute beginner20 min

V5. How to Tell AI What You Actually Want

Learn the simplest form of a useful coding specification.

Step 1 — Describe the screen

Example: “I want a white page with a heading at the top, a centered card, a text input, and a blue button.”

Step 2 — Describe the behavior

Example: “When the button is clicked, read the text and display it underneath.”

Step 3 — Describe restrictions

Example: “Keep it mobile friendly. Do not use external libraries. Keep the existing design.”

Step 4 — Describe what must not change

This becomes especially important when editing an existing project: “Do not remove the current navigation, data, or working features.”

Step 5 — Ask for a plan before a large change

For bigger projects, ask: “First explain which files need changing and why. Wait for me before making unrelated changes.”

Practice: Rewrite “Make my website cooler” into three concrete instructions: what should appear, what should happen, and what should stay unchanged.
Absolute beginner20 min

V6. Your First Three Coding Ideas

Understand only three concepts that will appear constantly: variables, functions, and conditions.

Step 1 — A variable is a named box

let name = "Aryan";

Think: “Create a box called name and put this value inside.”

Step 2 — A function is a reusable instruction

function sayHello() {
  alert("Hello!");
}

Think: “Give this group of instructions a name so I can run it later.”

Step 3 — An if statement is a decision

if (score > 10) {
  console.log("High score");
}

Think: “Only do this if the condition is true.”

Step 4 — Do not memorize syntax

At this stage, your goal is recognition, not memorization. When you see these concepts in AI-generated code, you should roughly know what they mean.

Beginner test: Can you explain these three ideas using ordinary language? Variable = named box. Function = reusable instructions. If = decision.
Absolute beginner20 min

V7. How to Make AI Change Existing Code Safely

Learn the safest beginner workflow for modifying a project.

Step 1 — Save the working version

Before a big change, make sure you can return to the version that currently works.

Step 2 — Describe the current behavior

Tell the AI what already works. Example: “The search works and the navigation works. Keep both unchanged.”

Step 3 — Request one change

Ask for one feature or one fix at a time.

Step 4 — Test immediately

Do not stack five untested changes. If something breaks, you want to know which change caused it.

Step 5 — Ask the AI to explain the change

Useful question: “Which files did you change, what did you change in each one, and why?”

Common mistake: Saying “fix everything” when you cannot yet tell what changed. Large uncontrolled edits make learning and debugging much harder.
Absolute beginner20–30 min

V8. When Your AI-Coded App Breaks

Learn what to do when the screen is blank, a button fails, or an error appears.

Step 1 — Do not panic

Breaking code is normal. Professional developers break things too. The skill is learning how to locate the problem.

Step 2 — Describe exactly what happened

Bad: “It doesn't work.” Better: “The page loads, but clicking Search does nothing. Before my last change, Search displayed results.”

Step 3 — Copy the exact error

If the browser or terminal shows an error, give the AI the exact message. Do not paraphrase technical errors if you can avoid it.

Step 4 — Tell AI the last change

The last known change is valuable evidence.

Step 5 — Ask for the smallest fix

Say: “Identify the likely cause, explain it in beginner terms, and make the smallest change that fixes it. Do not rewrite unrelated files.”

Golden debugging prompt:
I am a beginner. This worked before my last change.
Now [describe exact behavior].
The exact error is: [paste error].
Please explain the likely cause simply,
then make the smallest safe fix.
Do not remove working features.
Beginner20 min

V9. GitHub Without the Confusing Words

Understand just enough GitHub to save and share a vibecoded project.

Step 1 — What is GitHub?

GitHub is a platform where code projects can be stored, shared, reviewed, and changed over time.

Step 2 — What is a repository?

A repository, often called a repo, is a project space containing your files and their history.

Step 3 — What is a commit?

A commit is like a named checkpoint saying, “This is what my project looked like at this moment.”

Step 4 — What is GitHub Pages?

For compatible static projects, GitHub Pages can publish website files so other people can open the site through a web address.

Step 5 — Keep the beginner workflow simple

For now, remember only: edit → test → save checkpoint → publish. You can learn branches, merges, pull requests, and advanced Git later.

Security warning: Never put private API keys, passwords, or other secrets into a public repository.

V10. Your First Complete Vibecoding Project

Follow the entire beginner loop from an idea to a working tiny application.

Step 1 — Choose one tiny idea

Build a counter, to-do list, quote viewer, calculator, simple quiz, or greeting page. Pick something with one main purpose.

Step 2 — Ask AI for the smallest version

Tell it your skill level and ask for a plain HTML/CSS/JavaScript version unless you have a reason to use something more complicated.

Step 3 — Create the files

Let the AI explain which files you need. Create them exactly where instructed.

Step 4 — Run it

Open the page or use the project's documented run command. Your first goal is simply to see something working.

Step 5 — Add one feature

Ask for exactly one improvement. Test it.

Step 6 — Break and fix something

Use the debugging lesson. Give the AI the exact symptom and error.

Step 7 — Ask AI to explain your own project

Ask: “Explain my project as if I am completely new. What does every file do? How does clicking the main button travel through the code?”

Step 8 — Save a checkpoint

Keep a known-working version. This gives you confidence to experiment.

You are not expected to become a programmer in one day. The first goal is simply to understand the loop: idea → prompt → code → run → observe → explain → improve → save.

🎯 Vibecoding beginner checklist

  1. I understand that code is instructions.
  2. I know what a file and folder are.
  3. I roughly understand HTML, CSS, and JavaScript.
  4. I can describe one tiny feature clearly.
  5. I can ask AI to explain its changes.
  6. I can test one change at a time.
  7. I can report an error precisely.
  8. I understand that public code must not contain private secrets.
  9. I know what a GitHub repository is.
  10. I can follow the idea → prompt → test → fix → repeat loop.
